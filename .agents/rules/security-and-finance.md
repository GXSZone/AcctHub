# AcctHub 资金安全、并发一致性与多租户安全规范

AcctHub 属于多级代理发卡与数字订阅交易平台，涉及真实资金、虚拟卡密资产与多租户隔离，必须遵守金融级安全底线：

## 1. 资金守恒与高并发原子操作

1. **金额精度**：全站金额运算统一通过 `shared/domain/money.ts` 精确舍入至 2 位小数（USDT 唯一尾数使用 4 位小数），严禁直接对浮点数做连加连减后落库。
2. **原子条件更新（CAS）防并发双花**：
   - 钱包扣款必须带 `WHERE balance >= ?` 原子条件并校验受影响行数，确保全站余额永远 `>= 0`；
   - 卡密分配、优惠券核销、充值 CDK 兑换必须使用 `WHERE status = 'available'`（或使用次数上限）原子认领并检查 `changes`；
   - 异步支付单回调必须以 `status = 'pending' -> 'paid'` 原子锁保证严格幂等，重放回调直接返回已支付结果，绝不重复发卡或重复入账。
3. **付款后扣库与缺货补偿**：
   - 异步在线支付下单仅创建 `pending_payment` 订单与 `payment_intents`，**不提前锁死库存或核销优惠券**；
   - 支付回调验签成功后执行扣库与履约；若极端并发导致无货，必须自动将实付金额全额退回会员站内钱包（或游客单标记人工异常处理）并写入账本流水。

## 2. 支付网关与回调安全

- **强制验签与防重放**：易支付验证 MD5 签名与金额一致；Stripe 验证 `Stripe-Signature` HMAC-SHA256 与 5 分钟时间戳窗口；USDT TRC20 验证链上收款地址、合约、交易哈希唯一性与 4 位小数尾数金额精确匹配。
- **生产沙盒硬隔离**：本地沙盒模拟回调、免回调直充、演示一键入账等能力仅允许在非生产环境生效，生产环境一律返回 `403` 拒绝。

## 3. 多租户隔离与 RBAC 鉴权

- **严格租户与身份隔离**：会员订单、钱包账单、工单、2FA 凭证库必须严格绑定 `user_id`；严禁仅凭未验证的 `contact_email` 认领他人历史订单或泄露加密卡密。
- **最小权限原则**：总控管理接口必须验证 `role === 'admin'`；代理后台与分站配置接口必须验证有效代理身份且仅能操作本租户及下属分站资源，杜绝 IDOR 水平越权。
- **防爆破与敏感信息保护**：登录、查单、发信、支付创建等高频公开接口保持限流；密码使用强哈希加盐，卡密与 2FA 密钥加密落库，响应体与日志严禁输出明文密钥、私钥或内部堆栈。

## 4. 内容与导出安全

- 所有用户/后台输入的富文本 HTML 在前端渲染前必须经 `DOMPurify` 净洗；
- 所有 CSV 导出（财务对账单、订单表等）必须添加 UTF-8 BOM（`\uFEFF`）并对以 `=`、`+`、`-`、`@`、`\t`、`\r` 开头的单元格前置单引号防御 Excel 公式注入。
