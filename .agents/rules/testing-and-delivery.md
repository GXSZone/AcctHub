# AcctHub 测试防线、质量门禁与交付规范

## 1. 三层自动化测试防线

1. **纯领域与契约单元测试（Vitest）**：覆盖金额运算、质保计算、签名/防重放、Zod 契约、多语种字典键对称性与三级回退逻辑。
2. **后端真实数据库集成测试（Vitest + 本地 SQLite/D1）**：所有重构或新增的后端领域（`worker/domains/<domain>/`）必须配套路由级集成测试，直接基于 `migrations/` 权威建表验证真实 HTTP 请求与数据库状态变化，重点覆盖：
   - 正常业务闭环与边界输入校验（400/401/403/404/409）；
   - 并发幂等与资金守恒（防双花、防负余额、重复回调幂等）；
   - 跨租户与越权隔离。
3. **核心用户旅程端到端测试（Playwright E2E）**：覆盖 C 端 5 语种切换与下单发卡、异步收银台回调、会员中心、代理分站、上游管理与总控财务对账，要求控制台零报错、页面无频闪。

## 2. 提交前强制质量门禁

任何里程碑或功能提交前，必须依次通过全部门禁且达到零错误、零警告：

1. `pnpm run lint`（Biome 格式化与静态检查：**0 error, 0 warning**）
2. `pnpm run typecheck`（TypeScript 严格类型检查：**0 error**）
3. `pnpm run arch:check`（架构守卫脚本：模块体积软评估、0 裸 SQL、分层依赖、零硬编码中文与 5 语种键对称校验）
4. `pnpm run test`（Vitest 全量单测与集成测试全部通过）
5. `pnpm run build`（Cloudflare Worker SSR 包与客户端生产包构建成功）
6. 涉及前后端核心交互或大版本里程碑时，额外执行 `pnpm run test:e2e` 验证通过。

## 3. 工程交付纪律

- **小步原子提交**：按独立领域或明确里程碑分批提交，每笔提交自带完整测试并通过全部门禁，确保随时可回滚；
- **禁止破坏既有测试**：遇到测试失败必须定位根因并修复代码或同步更新合理契约，严禁通过删除断言、跳过测试（`test.skip`）或放宽 Lint 规则来“假通过”；
- **环境清理**：本地实测启动的后台开发服务必须在验收完毕后释放端口；临时脚本与测试产物不得提交进 Git 仓库。
